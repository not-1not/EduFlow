# Rencana Implementasi: Rebuild Sistem KAS (Kas Kelas)

## Konteks
Sistem KAS Kelas saat ini ada di App.tsx dengan komponen ClassCashView (line 5543). Sistem ini mengelola dua jenis transaksi: **gemari** (Rp 500/hari) dan **infaq** (Rp 1.000/hari). Data disimpan di koleksi terpisah per bulan (`classCashTransactions_YYYY_MM`) di Firestore/DB lokal.

## Permasalahan / Kekurangan Saat Ini
1. Tidak ada kalender khusus gemari/infaq dengan tracking tanggal masuk sekolah
2. Tidak ada penanda otomatis untuk hari libur/tanggal merah
3. Proses perhitungan manual jumlah hari per bulan
4. Tabel pembayaran siswa belum terintegrasi dengan KAS
5. Tidak ada rekap otomatis per individu

## Persyaratan Baru (User Story)

### 1. Kalender Khusus Gemari & Infaq
- Kalender dengan daftar tanggal masuk sekolah
- Auto-marking tanggal merah/libur dengan keterangan "libur"
- Basis: hari kerja Senin-Jumat, kecuali tanggal merah/hari libur nasional
- Infaq khusus hari Jumat (kecuali libur)

### 2. Admin Controls
- Centang otomatis hadir (gemari/infaq) berdasarkan kalender
- Opsi "bebas bayar" / manual override
- Setting otomatis per siswa per bulan

### 3. Perhitungan Otomatis
- Di akhir bulan: hitung jumlah hari berdasarkan centang
- Dasar pembayaran = jumlah hari × tarif (gemari 500 / infaq 1000)
- Konversi otomatis ke rupiah

### 4. Tabel Pembayaran Siswa
- Gabungan semua bulan
- Filter by: seharusnya, belum bayar, sudah bayar (dalam hari)
- Konversi otomatis ke rupiah

### 5. Rekapitulasi Pembayaran Individu
- Jumlah nominal sudah dibayar
- Jumlah nominal belum dibayar
- Per bulan dan akumulatif

// MonthlySummary - ringkasan per bulan per siswa
export interface MonthlyPaymentSummary {
  id: string;

  year: number;

  gemariDaysActual: number;

  infaqDaysExpected: number;
  infaqDaysActual: number;

  totalExpected: number;
  totalActual: number;
  payments: {
    paymentId: string;
    amount: number;
    date: string;
    type: 'gemari' | 'infaq' | 'combined';
  }[];
  status: 'lunas' | 'belum_lunas' | 'lebih_bayar';

## Alur Kerja Baru

### Setup Awal (Admin)
1. Pilih kelas
2. Pilih bulan → sistem generate otomatis kalender
3. Kalender mark hari efektif (Senin-Jumat kecuali libur)
4. Khusus infaq: sistem auto-mark hari Jumat efektif
5. Sistem simpan ke `classCalendars`

### Proses Bulanan
1. Admin buka Monthly Tracker
2. Sistem load `classCalendars` untuk bulan tersebut
3. Tabel siswa muncul dengan centang otomatis (expected days)
4. Admin review:
   - Jika semua sesuai → klik "Terapkan Semua"
   - Jika ada siswa izin/sakit → uncentang manual
   - Jika ada penyesuaian khusus → override
5. Klik "Hitung & Simpan"
6. Sistem:
   - Hitung `gemariDaysActual` × 500
   - Hitung `infaqDaysActual` × 1000
   - Simpan ke `monthlyPaymentSummaries`
   - Generate transaksi di `classCashTransactions`

### Proses Pembayaran
1. Orang tua bayar ke sekolah (tunai/transfer)
2. Admin input di `StudentPayment`
3. Sistem auto-match ke `monthlyPaymentSummaries`
4. Status update: lunas/belum lunas
5. Notifikasi tunggakan (opsional)

### Rekap Individu
1. Buka Individual Recap
2. Pilih siswa
3. Tampilkan semua bulan
4. Per bulan: expected vs actual vs paid
5. Total nominal keseluruhan

## Perubahan di Database/Firestore

### Collections Baru
1. `classCalendars`
   - Document ID: `{classId}_{month}` (contoh: `class1_2026-01`)
   - Fields: classId, month, schedule[date], studentAttendance[studentId]

2. `monthlyPaymentSummaries`
   - Document ID: `{studentId}_{month}` (contoh: `student1_2026-01`)
   - Fields: studentId, month, gemariDays, infaqDays, amounts, status, payments[]

### Indexes Wajib
Firestore:
- `classCalendars`: composite index on (classId, month)
- `monthlyPaymentSummaries`: composite index on (studentId, month), (classId, status)
